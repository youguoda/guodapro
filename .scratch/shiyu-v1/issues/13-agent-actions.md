# 13 — agent 动作：对选中条目执行

**What to build:** 用户在管理窗口中选中一条或多条条目，交给 agent 执行一个**动作**——总结、合并成笔记、改写、建议标签——结果以流式呈现。这让用户查完资料后能直接得到整理结果，也让标签不必全靠手工维护。

**贯穿全项目的原则在此必须成立：只有用户明确选中的内容会被送出，未选中的永不外送。** 不存在任何自动的、后台的、逐条的处理。

动作复用 05 建立的流式后端接口，不另开一套。

**Blocked by:** 05, 07

**Status:** done（需先配置后端凭据，见票 05）

- [x] 可在管理窗口中选中单条或多条条目
- [x] 可对选中内容执行总结、合并成笔记、改写、建议标签
- [x] 结果以流式呈现
- [x] 建议的标签可一键采纳，也可逐个取舍
- [x] 未被选中的条目内容不出现在任何对外请求中（须有测试）

- [x] 复用 05 的流式接口，不另写一套调用与错误处理

## 贯穿全项目的原则，在这里由测试守住

**只有用户明确选中的内容会被送出。** 这不是一句承诺，是两条测试：

- 传给模型的请求体里包含选中的条目，且**不包含**未选中的内容；
- 跑完一整轮记录（复制英文、中文、代码、URL）之后，模型被调用的次数是 **0**。

第二条盯的是"不存在任何后台自动触发的对外请求"。通往模型的每一条路径都起于
一次用户选择加一次按钮点击，代码里没有别的入口。

## 复用同一条通道

按票里的要求，动作不另开一套后端。把传输从"翻译专用"抽成通用的
`IStreamingModel`，翻译与动作都从这里走——`OpenAiCompatibleBackend` 同时实现
两个接口，翻译只是在它上面套了一层提示词。

## 建议标签的解析

模型无论提示词说得多严，都会去加项目符号和编号。与其严格要求，不如解析时剥掉
——这比让用户面对一堆"1. 项目甲"便宜。过长的行（超过 24 字）被丢弃：那不像
标签，像句子；几个月后没人会用那种东西去筛选。

标签逐个采纳，不是全有或全无——模型给的五个里通常有两个是对的。

## 验证记录

Core 新增 15 项测试，全套 197 项通过。覆盖：只送选中内容、空选不发请求、
流式累积、agent 不可达时报错而不拖垮其余功能、意外异常转为消息、四种动作
各有提示词与标签、标签解析（逐行、剥项目符号与编号、去重、丢弃过长项、空输入）、
以及那条"整轮记录零次对外请求"。

进程级验证：管理窗口在加入动作面板与多选后仍正常打开。

**仍待人工冒烟**：填入凭据后多选条目、四种动作各跑一次、点击采纳建议标签。
