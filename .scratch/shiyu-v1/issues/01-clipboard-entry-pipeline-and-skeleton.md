# 01 — 剪贴板条目管道与应用骨架

**What to build:** 用户复制一段文字后，它被记录成一条**条目**并持久保存；重启应用后条目仍在。托盘区出现拾语图标，菜单中能看到最近几条记录。

这是本项目的第一条完整路径，它顺带确立此后所有开发所依赖的结构：Core 作为唯一被测对象、Platform 作为封装操作系统交互的端口、伪造 Platform 驱动测试、存储使用真实 SQLite。**这张票写下的测试将成为此后所有测试的范式，其写法值得额外斟酌**——项目此前没有任何 prior art。

**Blocked by:** None — can start immediately.

**Status:** done（托盘一条待人工冒烟验证，见下）

- [x] 复制一段文本后，产生且仅产生一条对应的条目
- [x] 条目记录了内容、来源应用、创建时间
- [x] 应用重启后历史条目完好
- [x] 连续快速复制多次，每一次都产生独立条目，无丢失无重复
- [x] 复制与上一条完全相同的内容时的行为有明确定义并被测试覆盖
- [ ] 托盘图标常驻，菜单可查看最近条目、可退出应用
- [x] Core 不直接调用任何操作系统接口，全部经由 Platform 端口
- [x] 测试通过伪造 Platform 驱动 Core，断言数据库中的真实状态
- [x] 存储层测试使用真实 SQLite（临时目录或内存库），不使用替身

## 未由本轮验证的部分

开发工具环境的进程**没有剪贴板访问权限**（`OpenClipboard` 返回
`CLIPBRD_E_CANT_OPEN`，连 `Get-Clipboard` 也失败），因此真实剪贴板链路
与托盘 UI 无法在此自动验证。spec 的测试决策一节早已预见这一点：
真实 Win32 行为与 UI 渲染只能靠手工冒烟验证。

已验证：应用可干净启动并常驻（未产生 `startup-error.log`），
`%LOCALAPPDATA%\Shiyu\` 下正确建出 `history.db`（含 WAL），
首次实测占用为工作集约 47 MB、专用内存约 12 MB。

**需要人工执行的冒烟检查**（约 30 秒）：

1. 运行 `src\Shiyu.App\bin\Debug\net9.0-windows\Shiyu.App.exe`
2. 在任意应用中复制几段不同的文字
3. 右键（或左键）点击托盘图标 → 菜单中应列出刚复制的内容，最新在上
4. 点击"退出拾语" → 应用退出，图标消失

任一步不符，`%LOCALAPPDATA%\Shiyu\startup-error.log` 是第一个该看的地方。
