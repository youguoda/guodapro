# 02 — 取词与粘贴的时序模块

**What to build:** 用户在任意应用中选中文字后按下热键，拾语取得这段文字并显示出来。无论取词成功还是失败，用户原本的剪贴板内容都被完整还原，且这次取词动作不在历史中留下任何条目。

**这是全项目技术风险最高的一张票。** 发出模拟按键之后，没有任何事件告知目标应用已经写完剪贴板，只能轮询加超时。等待过短则取不到，过长则发木。粘贴方向是同一类缺陷（需先将焦点交还原窗口再发送粘贴按键），因此两个方向由同一模块、同一套机制处理。

本票只需把取得的文字显示出来即可验证，不涉及翻译。

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] 全局热键可注册，且注册失败（被其他软件占用）时给出明确提示而非静默失败
- [ ] 选中文字按热键后，能取得该文字
- [ ] 取词过程中的剪贴板变化被**自我抑制**，不产生条目
- [ ] 取词完成后，用户原本的剪贴板内容被还原
- [ ] 目标应用响应缓慢时，在超时前仍能取到内容
- [ ] 目标应用始终不响应时，超时后放弃，还原剪贴板，并提示用户
- [ ] 没有任何选区时，能识别出"未取到内容"而非返回上一次的剪贴板内容
- [ ] 剪贴板被其他进程占用导致读写失败时，有确定的恢复路径且剪贴板被还原
- [ ] 上述每一条失败路径都有测试，且每条都断言原剪贴板内容已被还原
- [ ] 粘贴方向：能将指定内容送入调用前处于前台的窗口
- [ ] 取词与粘贴共用同一套时序与抑制机制，而非两份实现
