# 14 — 设置界面与开机自启

**What to build:** 用户在一个克制的设置界面中调整：热键、母语与目标语言、翻译后端与凭据、图片原图保留期、排除规则、开机自启、数据库位置。拾语默认开机自启——托盘常驻工具不自启等于没装——但用户可以关掉。

**设置项刻意保持克制**：不做主题、不做皮肤、不做高级参数面板。设置项越少，"小而精美"越可信。

## 云同步目录的警告

数据位置这一项有专门的检测：路径落在 OneDrive、Dropbox、Google Drive、
坚果云、百度网盘等同步目录里时，当场标红警告，保存时再确认一次。

这件事在别的应用里也许只是提示，在这里是要紧的：**历史不加密**，而拾语对用户的
承诺是"数据不离开本机"。把数据库放进同步目录会**悄无声息**地推翻这个承诺——
什么都不会报错，什么都看不出不同，而明文的剪贴板历史已经在别人的服务器上了。

检测按**完整路径段**匹配，不是子串：`D:\笔记\OneDrive迁移笔记` 不会被误报。
误报会训练用户忽略警告，那比不警告更糟。`OneDrive - 公司名` 这类企业版目录
按前缀识别，它们同样会同步。

## 凭据

已保存的凭据**不会被填回输入框**——那等于把它摊在屏幕上供人抄走。界面只显示
"已保存凭据"，留空表示不改动，填入才覆盖。用户因此不必为了改一个无关设置而
重新输入凭据。

## 开机自启以系统为准

勾选框读的是**注册表里的实际状态**，不是设置文件里的声明。两者可能不一致
（用户自己删过启动项），此时应当跟随现实，而不是与之争辩。写入失败也不假装
成功，而是明说"没能写入系统，请检查是否有安全软件拦截"。

写在每用户的 Run 项下：不需要提权、是用户去找"开机启动了什么"时会看的地方、
而且手工删除毫无难度。

## 热键即时生效

保存后三个热键整组重新注册，而非逐个比对差异——后者的代码比整组重来还多。
无法识别的热键只让那一个功能不可用，不拦启动。三个热键相同会被拒绝：重复注册
的第二个会静默失效，不如当场说清楚。

## 界面的克制

没有主题、没有皮肤、没有高级参数面板。设置项越少，"小而精美"越是一句应用
真能兑现的话。

## 验证记录

Core 新增 29 项测试，全套 226 项通过。覆盖：六种同步目录的识别与命名、普通
目录不误报、**仅含服务名的目录不误报**、大小写与斜杠方向无关；热键的多种写法
解析、格式化顺序固定、往返一致、各类非法输入归 null、**裸字母被拒绝**
（注册单个 `Z` 会夺走全系统的该按键）。

顺手修掉一个真 bug：`AppPaths` 里静态字段按声明顺序初始化，`_root = DefaultRoot`
排在 `DefaultRoot` 之前，导致数据根目录实际为 null。编译器警告点出来的。

进程级验证：应用启动后**自行把自启动项写入注册表**（路径带引号，防止含空格的
路径被截断），无启动错误。

**仍待人工冒烟**：设置窗口的实际布局、各项保存、同步目录警告的显示、热键改动
后立即生效。
