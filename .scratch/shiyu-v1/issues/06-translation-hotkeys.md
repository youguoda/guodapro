# 06 — 翻译热键：划词与逃生口

**What to build:** 两条显式触发的翻译路径。其一，用户在任意应用中选中文字后按热键，直接得到译文面板——这让用户读网页、PDF、聊天记录时不必先复制。其二，用户按下**逃生热键**，强制翻译当前剪贴板内容，不论徽标此前是否出现过。

逃生口是自然语言过滤器误判时的唯一兜底。没有它，用户无法区分"过滤器判断失误"和"程序出故障"。

**Blocked by:** 02, 05

**Status:** done（需先配置后端凭据，见票 05）

- [x] 选中文字按划词热键后，面板展开并流式显示译文
- [x] 取词失败时给出明确提示，而非静默无反应
- [x] 取词失败后原剪贴板内容完好
- [x] 划词动作不在历史中留下条目
- [x] 按逃生热键后，当前剪贴板内容被翻译并展示，不论徽标此前是否出现
- [x] 逃生口对被过滤器挡下的内容同样有效
- [x] 前台窗口为管理员权限进程时，划词无法取词，此时给出可理解的提示而非看似崩溃

## 两个热键

| 热键 | 作用 |
|---|---|
| `Ctrl+Shift+Z` | 划词翻译：取当前选区 → 面板 |
| `Ctrl+Shift+X` | 逃生口：翻译此刻剪贴板里的内容 |

逃生口**刻意不经过徽标的过滤器**——坚持要翻译正是这个热键存在的全部意义。
没有它，用户无从分辨"过滤器判断失误"与"工具坏了"，也没有办法表达异议。

## 管理员窗口这条路是走不通的

目标窗口若以管理员身份运行，而拾语没有，UIPI 会**静默丢弃**拾语发出的按键。
表现上与"没有选中内容"和"程序响应太慢"完全一样——站在外面无从区分。

因此提示语不去断言原因，而是把三种可能都列出来，并给出可行的替代动作
（复制之后按逃生口热键）。第三种是用户自己绝对猜不到的那种。

## 冲突一次报完

两个热键的注册冲突收集起来一并提示，而不是一个气泡接一个气泡；且**任何冲突
都不致命**——被别的软件占掉一个热键是再正常不过的事，不该拦住拾语启动。
