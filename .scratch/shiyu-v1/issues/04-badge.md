# 04 — 徽标：判定与显示

**What to build:** 用户复制一段英文句子后，光标附近出现一个小**徽标**，一两秒后自动淡出。复制代码、文件路径、URL、纯数字或中文时，徽标不出现。徽标不夺走焦点，用户在原应用中的选区与光标位置不受影响。

徽标本身不显示译文，只表示"这段内容可以翻译"。本票中点击徽标可暂不产生实际效果。

**关键不变量：条目的写入发生在过滤之前。** 过滤器只决定徽标弹不弹，绝不决定记不记——被过滤掉的内容**仍然**产生条目。搞反会让历史出现空洞。

## 判定规则

纯字符统计，不引模型——它要在每一次复制上运行，一个要花几百毫秒才能决定的
徽标本身就已经失败了。规则**偏向沉默**：徽标该出而未出，代价是按一次逃生热键；
徽标整天压在代码、路径和数字上，代价是整个工具让人想关掉。

识别顺序：URL → 文件路径 → 无字母（数字与符号）→ 母语占比 → 代码特征 → 自然语言。

踩到一个坑：最初"无字母"用的是 `[^A-Za-z]`，而**中文不含拉丁字母**，于是每一
句中文都被判成纯数字。改用 Unicode 感知的字母判定后即正确——中文字符本身就是
字母。三条中文用例把这个问题当场钉出来了。

母语阈值取 15% 且刻意偏低："请 review 一下这个 pull request"这种夹杂写法，
对这位用户而言本来就读得懂，不该打扰。

## 不变量：过滤只管徽标，不管记录

`ClipboardPipeline.BadgeDeserved` 在**记录之后**触发，且排除规则先于二者。
因此：被排除的内容既不记录也不弹徽标；被过滤的内容**照常记录**、只是不弹。
这两条各有独立测试，因为搞反任一条都会让历史出现用户既看不见也解释不了的洞。

## 不抢焦点

`ShowActivated=False` 管得住首次显示，`WS_EX_NOACTIVATE` 管得住此后的一切——
**点击徽标不能把焦点从用户正在输入的地方抢走**。两者都设。

定位用物理像素经 `SetWindowPos`，绕开 WPF 的缩放坐标系；贴边时**翻转**到光标
另一侧而非简单钳制（钳制会把徽标塞到指针底下吞掉下一次点击），翻转越界后再钳制。
应用清单声明 PerMonitorV2，使不同缩放的显示器上内容尺寸正确。

鼠标悬停时暂停淡出计时——那是用户在说"等一下，我在看"。
