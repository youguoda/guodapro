# 拾语 (Shiyu) v1 — Spec

Status: ready-for-agent

> 术语一律以 `CONTEXT.md` 为准。决策依据见 `docs/adr/0001` ~ `0007`。

## Problem Statement

用户在 Windows 上每天大量复制文字，面临两个互相纠缠的麻烦。

**第一，看不懂的东西要翻译，但现有办法都别扭。** 复制一段英文后，要么切到浏览器打开翻译网站再粘贴，要么打开一个翻译软件。无论哪种，都打断了正在做的事。市面上"复制即自动翻译"的工具又走向另一个极端：用户一天里绝大多数复制是代码、文件路径、URL、命令行，这些被无差别翻译后产生的噪音，会让人在三天内卸载它。

**第二，复制过的东西找不回来。** Windows 原生剪贴板历史容量有限、不能分类、不能搜索、图片支持弱。用户想找"上周复制过的那段配置"或"那张截图"时无从下手，只能重新去源头找一遍。

这两件事都挂在同一个剪贴板监听上，但对触发的要求相反：历史要贪婪地记下每一次复制，翻译要克制到只在真正需要时出现。现有工具通常只做好其中一件。

用户同时有一条贯穿的硬性要求：这是个**托盘常驻**的工具，必须占用内存小、响应快、小而精美。

## Solution

**拾语**是一个 Windows 托盘常驻工具，用一套剪贴板监听同时服务两个职责，并以"未经用户明确动作的内容永不离开本机"为贯穿原则。

**翻译侧。** 复制后，若内容像自然语言且不是中文，光标旁出现一个**徽标**——它本身不显示译文，只表示"这段可以翻译"，一两秒后自动淡出。点击徽标才展开**面板**，译文以流式逐字长出，首字很快到达，用户全程在读而不是在等。划词翻译由显式热键触发，取词通过模拟 `Ctrl+C` 实现。另有一个**逃生热键**强制翻译当前剪贴板内容，用于过滤器误判时兜底。

**剪贴板侧。** 每一次复制都被记为**条目**，不论徽标是否出现，涵盖文本、图片、链接、文件路径。历史有两个入口，各尽其职：**快速条**由热键唤出、贴在光标旁、键盘上下选、回车粘贴后立即消失，服务每日数十次的快速粘贴；**管理窗口**由托盘图标打开，含筛选器、标签、批量选择，服务每周数次的翻检整理。文本永久保留，图片缩略图永久保留，图片原图有保留期。

**agent 侧。** 本地 agent 有两个位置：作为翻译后端的第二实现（离线或隐私场景），以及对用户**明确选中的条目**执行**动作**——总结、合并成笔记、改写、建议标签。不存在任何自动的、后台的、逐条的 LLM 处理。

## User Stories

### 翻译：徽标与面板

1. 作为拾语用户，我想在复制一段英文后于光标旁看到一个徽标，以便我知道这段内容可以翻译而不必主动去想。
2. 作为拾语用户，我想让徽标在一两秒后自动淡出，以便我不理它时它不会留在屏幕上碍事。
3. 作为拾语用户，我想让徽标在我复制代码、文件路径、URL、纯数字时不要出现，以便我一天中绝大多数复制不被打扰。
4. 作为拾语用户，我想让徽标只在内容不是中文时出现，以便我复制中文时不被无意义地提示。
5. 作为拾语用户，我想点击徽标后才看到译文，以便未经我确认的内容不会被送去翻译。
6. 作为拾语用户，我想让徽标出现在复制发生的位置附近，以便我想用时伸手就能点到。
7. 作为拾语用户，我想让徽标在多显示器、不同缩放比例下都出现在正确位置，以便我在副屏工作时它不会跑到主屏或显示模糊。
8. 作为拾语用户，我想让徽标和面板都不夺走焦点，以便我原应用里的选区和光标位置不被破坏。
9. 作为拾语用户，我想看到译文逐字长出而不是干等，以便一两秒的等待感觉像在阅读而不是在卡顿。
10. 作为拾语用户，我想在译文流到一半出错时仍看到已经到达的部分并得到明确的错误提示，以便我知道发生了什么而不是面对一个半截的句子。
11. 作为拾语用户，我想在面板里同时看到原文，以便我能对照阅读。
12. 作为拾语用户，我想一键复制译文，以便我能直接拿去用。
13. 作为拾语用户，我想在面板里切换翻译方向，以便我偶尔需要中译外时不必另找工具。
14. 作为拾语用户，我想让译文只是译文，不要附带解释、多个版本或扩写，以便我得到的是翻译而不是一篇小作文。
15. 作为拾语用户，我想按下逃生热键就强制翻译当前剪贴板内容，以便过滤器判断失误时我仍有办法。
16. 作为拾语用户，我想在面板打开时按 Esc 关掉它，以便我能迅速回到工作。

### 翻译：划词

17. 作为拾语用户，我想在任意应用中选中文字后按热键即可翻译，以便我读网页、PDF、聊天记录时不必先复制。
18. 作为拾语用户，我想让划词取词不污染我的剪贴板，以便我正在复制的东西不会被划词动作冲掉。
19. 作为拾语用户，我想让划词动作不在历史里留下垃圾条目，以便我的剪贴板历史保持干净。
20. 作为拾语用户，我想在取词失败时得到明确提示而不是静默无反应，以便我知道该换个方式而不是怀疑程序坏了。
21. 作为拾语用户，我想让取词失败时我原本的剪贴板内容被完整还原，以便一次失败的划词不会让我丢东西。

### 剪贴板：记录

22. 作为拾语用户，我想让每一次复制都被记录，不论徽标是否出现，以便我的历史没有洞。
23. 作为拾语用户，我想让文本、图片、链接、文件路径都被记录，以便我不必为不同类型的内容用不同工具。
24. 作为拾语用户，我想让密码管理器复制的内容不被记录，以便我的密码不会被永久存在磁盘上。
25. 作为拾语用户，我想能自己配置"不记录"的规则（按来源应用或内容模式），以便我能把银行、支付这类窗口排除在外。
26. 作为拾语用户，我想让常用的排除规则开箱就有，以便我不必自己从零配一遍才安全。
27. 作为拾语用户，我想让文本条目永久保留，以便我几年后仍能搜到。
28. 作为拾语用户，我想让图片缩略图永久保留，以便我的历史列表永远完整、不出现空洞。
29. 作为拾语用户，我想让图片原图在一段时间后自动清理，以便这个工具不会悄悄吃掉我几十 GB 硬盘。
30. 作为拾语用户，我想能自己设定原图保留期，以便我按自己的硬盘情况决定。

### 剪贴板：快速条

31. 作为拾语用户，我想按热键就在光标旁唤出快速条，以便我粘贴历史内容时手不离开当前位置。
32. 作为拾语用户，我想用键盘上下选择条目、回车粘贴，以便整个操作不需要碰鼠标。
33. 作为拾语用户，我想让快速条在粘贴后立即消失，以便它不打断我的节奏。
34. 作为拾语用户，我想让粘贴动作把内容送到我原来正在输入的地方，以便粘贴真的生效而不是丢进空处。
35. 作为拾语用户，我想在快速条里直接输入关键词过滤，以便条目多时我也能迅速定位。
36. 作为拾语用户，我想按 Esc 关掉快速条而不粘贴任何东西，以便我改主意时不留痕迹。

### 剪贴板：管理窗口

37. 作为拾语用户，我想点击托盘图标打开完整的管理窗口，以便我翻检整理时有足够的地方展开。
38. 作为拾语用户，我想用关键词搜索全部历史，以便我能找回很久以前复制的东西。
39. 作为拾语用户，我想按日期筛选，以便我能定位"上周那段配置"。
40. 作为拾语用户，我想按内容类型筛选，以便我能只看图片或只看文本。
41. 作为拾语用户，我想组合多个筛选条件，以便我能精确锁定目标。
42. 作为拾语用户，我想给条目打标签（按项目、按用途），以便我的历史井井有条。
43. 作为拾语用户，我想把高频使用的条目置顶，以便它们始终优先出现。
44. 作为拾语用户，我想在列表里直接看到图片条目的缩略图，以便我一眼认出是哪张而不必逐个打开。
45. 作为拾语用户，我想把图片条目直接拖到资源管理器保存成文件，以便我不必先打开再另存。
46. 作为拾语用户，我想删除单个条目，以便我能清掉不想留的东西。
47. 作为拾语用户，我想按时间段批量删除，以便我能清理某一段时期的记录。
48. 作为拾语用户，我想一键清空全部历史，以便我在需要时能彻底抹干净。
49. 作为拾语用户，我想在管理窗口里重新粘贴或复制任意条目，以便它是个真正可用的入口而不只是个查看器。

### agent 动作

50. 作为拾语用户，我想选中一条或多条历史条目后交给 agent 处理，以便我能把零散收集的内容变成有用的东西。

52. 作为拾语用户，我想让 agent 总结我选中的内容，以便我能快速抓住要点。
53. 作为拾语用户，我想让 agent 给我选中的条目建议标签，以便我不必自己维护整套标签体系。
54. 作为拾语用户，我想让 agent 只处理我明确选中的内容，以便我没选的东西永远不会被送出去。
55. 作为拾语用户，我想让 agent 的输出也是流式的，以便长内容处理时我不必干等。

57. 作为拾语用户，我想能切换翻译后端（云端或本地 agent），以便我在隐私敏感或离线时有别的选择。

63. 作为拾语用户，我想看到一个克制的设置界面，以便我不必在一堆用不到的选项里找我要的那个。

### 系统行为

64. 作为拾语用户，我想让拾语常驻托盘且占用内存小，以便它整天开着也不影响我的机器。

66. 作为拾语用户，我想让历史增长到很大之后搜索依然快，以便这个工具用得越久越有价值而不是越来越慢。
67. 作为拾语用户，我想让我的数据存在本机专属位置、不被云同步带走，以便我不加密的历史不会意外上云。
68. 作为拾语用户，我想在拾语崩溃或被强制结束后重启时历史完好，以便我不会丢数据。

## Implementation Decisions

### 分层与端口

- **Core** 是唯一被测对象，持有全部业务逻辑：剪贴板管道、取词时序、徽标判定、翻译与动作调度、条目与标签的读写、保留策略。Core 不依赖任何 UI 框架，也不直接调用 Win32。
- **Platform 端口**封装全部操作系统交互：剪贴板读写、剪贴板变化事件、`SendInput`、热键注册与回调、光标位置、排除标记探测、前台窗口焦点操作。
- **TranslationBackend 端口**封装全部网络交互，**接口是流式的**（见 ADR-0002）。翻译与 agent 动作共用这一个端口形状（见 ADR-0005）。
- **Store** 直接使用 SQLite，不做端口抽象。全文搜索、多维筛选、过期清理属于"伪造了就等于没测"的逻辑，必须测真的。
- **UI** 是 Core 的薄消费者：接收"显示徽标于某坐标""以流填充面板""条目集已变更"一类指令，自身不含判定逻辑。

### 剪贴板管道

剪贴板变化事件到达后依次经过：自我抑制检查 → 排除标记检查 → 排除规则检查 → 写入条目 → 自然语言过滤器 → 语言检测 → 徽标判定。

**写入条目发生在过滤之前**：过滤器只决定徽标弹不弹，不决定记不记（见 ADR-0001）。

### 取词时序（风险最高）

置起自我抑制标志 → 保存当前剪贴板内容 → `SendInput` 发送 `Ctrl+C` → 轮询等待剪贴板变化（带超时）→ 读取取得的文本 → 还原原剪贴板内容 → 解除抑制标志。

**没有任何事件告知目标应用已写完剪贴板**，只能轮询加超时。超时、目标应用不响应、取得内容为空或与原内容相同（说明没有选区）——每一条都必须有确定的恢复路径，且**任何路径下原剪贴板内容都必须被还原**。

### 粘贴时序（同类风险）

快速条与徽标/面板的焦点规则相反：**快速条必须接受焦点**以支持键盘导航。粘贴时须先将焦点交还原窗口，再 `SendInput` 发送 `Ctrl+V`。

这与取词时序是**同一类缺陷**，由同一模块、同一套机制处理（见 ADR-0007）。二者共同构成本项目最大的技术风险，应最先实现。

### 窗口

- 徽标与面板：置顶且不接受激活（`WS_EX_NOACTIVATE` + `WS_EX_TOPMOST`），由 P/Invoke 设置窗口扩展样式实现。
- 徽标定位须 per-monitor DPI aware，多显示器混合缩放是明确的正确性要求而非优化项。
- 快速条：接受焦点，贴光标。
- 管理窗口：常规窗口。

### 数据模型

条目表记录类型、文本内容、来源应用、创建时间、置顶标志。图片条目关联两份 blob：缩略图（永久）与原图（有保留期），原图以文件形式存于磁盘——**这使"拖到资源管理器"退化为拖一个已存在的文件路径（`CF_HDROP`），无需实现 OLE 虚拟文件**（见 ADR-0006）。标签与条目多对多。文本内容另建全文索引表。

保留策略以后台作业执行，只清理过期原图，不触碰条目与缩略图。

### 存储位置

`%LOCALAPPDATA%\Shiyu\`。数据不加密，故"不离开本机"完全依赖放对位置（见 ADR-0007）。若日后提供自定义位置，选中同步目录必须警告。

### 翻译后端

首个实现复用用户已有的阿里云 MaaS (qwen) 凭据。prompt 必须强制"只输出译文"，压制加戏——这是需要测试覆盖的约束，不是随手写的一句提示词。

## Testing Decisions

### 什么是好测试

**只测外部可观察的行为，不测实现细节。** 测试驱动 Core 的对外接口，断言 Core 产出的指令与数据库中的实际状态，不断言 Core 内部调用了什么、以什么顺序调用。一个好测试在重构内部结构后依然通过，在行为变坏时立刻失败。

### 缝与替身

**只有一道缝：Core 的对外接口。**

- **伪造 Platform** —— 测试借此模拟真实世界的恶劣情况：目标应用慢半拍才写剪贴板、压根不写、写入错误内容、剪贴板被别的进程占用、热键注册失败、光标位于副屏且缩放不同。
- **伪造 TranslationBackend** —— 模拟正常流、流到一半中断、超时、后端返回夹带解释的"加戏"输出。
- **真实 SQLite**（临时目录或内存库）—— 全文搜索、多维筛选、过期清理必须测真的。

### 必须覆盖的场景

- 取词时序的每一条失败路径，且每条都断言**原剪贴板内容被还原**。
- 自我抑制：应用自己造成的剪贴板变化不产生条目。
- 排除标记与排除规则：命中时不写入条目。
- 徽标判定：代码/路径/URL/纯数字不弹；中文不弹；英文自然语言弹。
- 写入与过滤的独立性：被过滤掉的内容**仍然**产生了条目。
- 流式：首块到达即可呈现；中断后保留已到达部分并报错。
- 检索：关键词、日期、类型的单条与组合筛选。
- 保留策略：过期原图被清理，条目与缩略图不受影响。

### Prior art

**无。** 这是绿地项目，第一批测试将确立此后所有测试的范式，因此第一张票的测试写法值得额外斟酌。

## Out of Scope

- **UIA 取词路径。** 已明确只走模拟 `Ctrl+C`（ADR-0003）。
- **数据库加密。** 已明确不加密（ADR-0007）。SQLCipher 是记录在案的回头选项，不在 v1。
- **自动的、后台的、逐条的 LLM 处理**，包括自动归纳与自动打标签（ADR-0005）。
- **主题、皮肤、高级参数面板。** 设置项刻意保持克制。
- **界面多语言。** v1 仅中文界面。
- **云同步、跨设备。**
- **跨平台。** 仅 Windows。
- **OCR / 截图翻译。**
- **选中即翻**（鼠标抬起自动取词）。已否决（ADR-0003）。
- **替换 `Win+V`。** `Win+` 组合被 shell 保留，不做争抢。
- **提权应用中的划词。** `SendInput` 被 UIPI 阻挡，这是硬边界，不是缺陷。

## Further Notes

### 三处未经核实的前提

用户选择跳过技术调研，以下判断均为先验，**实现前需核对一手来源**：

1. **排除标记的确切格式名与行为**（`ExcludeClipboardContentFromMonitorProcessing`、`CanIncludeInClipboardHistory` 一类）。**这一条关系到用户的密码是否会被存盘，优先级最高。**
2. 各技术栈的常驻内存与启动耗时量级（曾据此选定 Qt，现已由 ADR-0008 改为 WPF）。
3. UIA 在各类应用中的覆盖率（虽已不走此路，但它是 ADR-0003 决策的背景）。

### 记录在案的回头选项

- **C# / WPF** —— 若"做完"的压力超过"省内存"（ADR-0006）。
- **SQLCipher 整库加密** —— 若隐私顾虑上升（ADR-0007）。

### 性能指标的正确含义

托盘常驻程序的冷启动每日仅发生一次（登录时）。真正被感知的是**热路径**——按下热键到界面出现。性能工作应投在热路径与常驻内存，而非冷启动（ADR-0006）。

### 已知的产品风险

手工维护标签体系普遍难以长期坚持。v1 仅以"选中后请 agent 建议标签"部分缓解。若该风险成真，需重新审视 ADR-0005 中"不做自动打标签"的决定。
