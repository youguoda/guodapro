# 拾语 v2：对齐并超越 EcoPaste

## 这一轮要做什么

v1 交付了拾语的骨架与差异化能力：剪贴板管道、排除标记、徽标与翻译面板、
划词与逃生口、管理窗口、快速条、图片条目、标签与置顶、保留策略、agent 动作、
设置与单实例保护。共 15 张票，约 9.3k 行，226 项测试。

v2 的目标是**在功能广度上全面对齐参照实现 EcoPaste，并在它没有的方向上继续拉开**。

## 参照实现的评估结论

评审对象：`EcoPasteHub/EcoPaste` @ `5139d30`（2026-08-12）· v1.1.0 · Apache-2.0
产品代码约 43k 行（Rust 22.6k + TS/TSX 20.5k），是拾语当前体量的 4.6 倍。

**必须知道的背景**：其 v1.0.0（2026-07-03）是一次**彻底重写**，实际代码年龄约三个月，
版本号不代表沉淀。重写中砍掉了 Linux，语言收缩到两种，数据库 schema 重置为单一迁移。

### 决定借鉴的设计

| 设计 | 为什么值得 | 落在哪张票 |
|---|---|---|
| 按住修饰键把图标原地换成快捷键 | 零 UI 成本教会整套键盘模型，且提示与行为绑在同一处不会漂移 | 14 |
| 设置即数据 | 搜索、深链、引导复用三件事白送；写成硬编码界面则要各写一遍且各自腐烂 | 22, 23, 27 |
| Escape 是层级栈不是关闭键 | 用户按 Esc 想撤销的是刚才那一步，不是整个会话 | 15 |
| 悬停 240ms 缓冲与重定位 | 相邻卡片之间移动时预览滑过去而非闪一下，成本极低、感知差别巨大 | 17 |
| 面板尺寸预测而非测量 | 图片宽高本就在库里，面板可在解码前就位，没有跳一下 | 17 |
| 跨窗口连接线 | 键盘快速移动时"这显示的是哪一条"的困惑被一条线消解 | 01, 18 |
| 空状态文案矩阵 | 空状态是最需要帮助的时刻，也最容易被敷衍 | 16 |
| 备注盖在原文之上 | 写了备注的条目，用户记住的是备注不是原文 | 10 |
| 删除保护建模为数据 | 被保护的条目直接不显示删除入口，比显示成灰的更清楚 | 21 |
| 降低动效全覆盖 | 漏做则对动效敏感的用户是一次伤害，而他们通常不报告只卸载 | 05 |

### 决定不借鉴的

- **视觉身份**：参照实现是纯 Ant Design 默认值，零 token 覆盖、无自定义字体、无主色。
  这是它自己的短板，也是我们的机会——见票 04。
- **拖出无任何提示**：功能完整但无手柄、无光标变化、无幽灵图，实际无法被发现。
  票 20 把可发现性直接写进验收，作为反面教材的对照。
- **声明与渲染脱节**：十一项声明为分段控件的设置被统一渲染成下拉框，数据层的设计意图白写。
  票 22 明确要求声明什么就渲染什么。
- **骨架屏不闪**、**英文空状态占位符损坏**：实现质量问题，不构成设计参考。

### 我们已经领先、需要守住的

| | 拾语 | EcoPaste |
|---|---|---|
| 遵守系统剪贴板排除标记 | 是，含四情况真实验证 | **完全未实现** |
| Windows 出厂密码管理器名单 | 11 条预设 | **默认为空** |
| 主排序路径索引 | 有 | 无 |
| 翻译与 agent | 完整一条线 | 无 |

其中**排除标记**这一条最要紧：参照实现只靠保守的内容正则与用户手工配置的忽略名单，
而一个从密码管理器复制出来的随机口令两者都命中不了，结果是明文落盘。

## 技术前提

三项能力**尚未实证**，决定了视觉方向是否成立，因此排在最前作为验证票：

1. 跨窗口穿透覆盖层——面板可点、面板之外穿透（票 01）
2. 虚拟化列表的粘性置顶与逐项动画（票 02）
3. 背景模糊与非激活窗口叠加（票 03）

三者任一不成立，对应的设计需要退化方案，票内已要求写明。

## 不变的约束

v1 确立的架构与原则**全部继续有效**：

- Core 目标 `net9.0`（不带 `-windows`），由编译器强制它不碰操作系统；
- 业务逻辑放 Core 并可在无界面下测试，平台交互收在端口后；
- 存储直接使用 SQLite，不做端口抽象；
- 迁移只增不改，升级不得丢失用户历史；
- 排除先于记录，过滤只决定徽标不决定记录；
- 只有用户明确选中的内容会离开本机，不存在后台自动外送。
