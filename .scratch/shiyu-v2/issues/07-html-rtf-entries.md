# 07 — HTML 与富文本条目

**What to build:** 从网页或文档复制带格式的内容时，保留其 HTML 或 RTF 形式。
用户既能**按原格式粘贴**（回到支持富文本的地方仍有样式），也能**按纯文本粘贴**
（去掉所有格式）。列表中显示的是可读的纯文本摘要，不是标签源码。

## 两条必须守住的线

**其一，HTML 必须净化后才渲染。** 剪贴板上的 HTML 来自任意网页，
直接渲染等于把不受控的内容放进自己的进程。摘要与预览都只显示净化后的文本。

**其二，写回剪贴板时要同时写纯文本回退。** 只写 HTML 的话，粘贴到纯文本编辑器里
会得到空白或乱码。这一点还牵连到自我抑制——一次写回产生多个格式，
回环抑制必须按内容指纹而非"写过一次"来判断。

## Comments

### 交付（2026-09-25）

**净化策略：从不渲染。** 列表与搜索显示的始终是 CF_UNICODETEXT 的纯文本
（浏览器/Word 复制时本来就同时发布），HTML 片段只作为"粘贴回富文本目的地"
的载荷保存——不渲染就没有注入面，比任何净化器都强。`ClipboardHtml`（Core
纯函数，4 项测试）负责 CF_HTML 头部的字节偏移解析与重建，多字节内容的
往返有测试钉住。

**存储（v6 只增迁移）**：`html`/`rtf` 列；**512KB 上限**——整页复制超过即弃
格式、纯文本照记（测试覆盖）；监听器读取时只取 fragment（头是传输层不是
内容）。写回 `SetRich`：一次 OpenClipboard 内写 纯文本 + HTML + RTF 三个
格式——纯文本回退永远在（纯编辑器不会拿到空白），单次通知 + 属主检查 +
文本指纹三重保证不产生重复条目（测试钉住多格式回环）。

**粘贴语义**（窄条托盘与键盘）：**粘贴/回车 = 按原格式**（有格式则
`SetRich` + 只发粘贴键，`SelectionCapture.PasteCurrentClipboard` 新入口）；
**纯文本粘贴/修饰键+回车 = `SetText` 全剥**。复制同理带格式。搜索与列表
零变化——本来就只用纯文本列。

**待人工**：从网页复制一段带粗体的文字 → 窄条看摘要仍是干净纯文本 →
回车粘贴到 Word/富文本编辑器看样式保留 → "文"按钮粘贴到记事本看纯文本 →
历史确认没有重复条目。
