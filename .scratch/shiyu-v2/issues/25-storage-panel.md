# 25 — 存储用量面板与轻量内存模式

**What to build:** 设置里有一处显示拾语实际占用了多少磁盘——数据库、图片原图、
缓存各占多少，以及可以点击直接打开所在文件夹。占用超过阈值时给出提示。

另外：**窗口隐藏后进入轻量状态**，释放不再需要的资源，把后台常驻内存压下去。

## 为什么把这两件事放一张票

它们回答的是同一个用户疑问：**"这个常驻的小工具到底吃了我多少资源？"**
磁盘的答案是一个面板，内存的答案是一个机制。分开做，两边都容易被忽略。

拾语选 WPF 时就明确记下了"常驻内存高于 C++ 方案，量级差异为数十 MB，
这是本次取舍中真实付出的代价"。轻量模式是把这个代价收窄的手段，
也是我们对当初那个取舍的交代。

## 实现记录（2026-09-26）

- 磁盘面板：设置·数据页「磁盘占用」（树声明 Custom 项），实测 history.db（含
  -wal/-shm）与 images/ 目录，数据库/图片原图/合计三行 + 「打开数据文件夹」
  「刷新」两个按钮；合计超 500MB 红字建议（缩短保留期或导出后清空）。
  缩略图存于库内 blob、随数据库一行计——不拆假账。
- 轻量模式：`Dismiss` 淡出完成、窗口确认不可见后——清空已现实化卡片集合
  （缩略图解码与行布局是窗口的全部开销）→ 后台 GC → `MemoryTrim.WorkingSet`
  （SetProcessWorkingSetSize(-1,-1) 归还页面）。召唤路径 `ReloadIfBehind(force)`
  本就整页重建，恢复无感；剪贴板监听与管线不在窗口里，隐藏期照录。
  界面页「轻量模式」开关（`LightweightWhenHidden` 默认开）。
- 探针实测：工作集 空闲 55.3MB → 呼出 186.7MB → 隐藏后 90.3MB（释放 96.4MB）；
  隐藏期间 SetText 入册、再召唤后条目在列且窗口响应正常；测试条目已清。
