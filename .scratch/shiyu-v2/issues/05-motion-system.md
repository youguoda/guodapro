# 05 — 动效体系与降低动效支持

**What to build:** 一套统一的动效规则：状态变化用一种时长与缓动，"重要时刻"用另一种；
以及**当系统设置为减少动画时，全部动效自动关闭**。

## 规则要少到能记住

参照实现整个应用只用两条曲线——普通状态变化一种、两处"主角时刻"（预览面板展开、
引导步骤切换）另一种。规则少，界面才会显得是一个整体而不是各处各做各的。

拾语沿用同样的克制：**两条曲线，两个时长档**，新增动效必须从中选，
选不出来说明这个动效不该加。

**降低动效不是可选项。** 参照实现每一处动画调用点都读了系统偏好，
每一条 CSS 过渡都带了对应开关——这件事一旦漏做，对动效敏感的用户就是一次伤害，
而且他们通常不会来报告，只会卸载。

## Comments

### 交付（2026-09-25）

**架构：三层各一段，一处配置。**

- `Shiyu.Core/DesignTokens`：两档时长（状态变化 160ms / 主角时刻 300ms，感知
预算有测试钉住）+ `MotionCurve` 枚举（恰两个成员，有测试钉住）+
`MotionPlan.Duration(animationsAllowed, feature)`——**每个动效都必须过问这一
处**，减少动画因此是全有或全无，不会漏成筛子（参照实现的教训）。6 项新测试。
- `Shiyu.Windows/UiAnimation.Allowed()`：每次实时读
`SPI_GETCLIENTAREAANIMATION`（设置 > 辅助功能 > 视觉效果 > 动画效果）。
单次系统调用，换"改设置立即生效、无需重启"。
- `Shiyu.App/Motion`：唯一的 WPF 动画配置点。Standard=CubicEase/EaseOut，
Feature=QuinticEase/EaseOut；减少动画时返回零时长动画（状态跳变仍然可见）。

**核心规则：出现即满值，离场才淡出。** 不是审美选择而是系统约束：分层窗口
当前表面全透明时 WPF 不给合成 tick（票 04 徽标从不显示的根因），从透明度 0
起步的淡入会永远冻结。面板原有的 110ms 淡入其实一直靠译文流不断重排"意外
续命"才显示出来——后端快或失败时它同样会冻住，已一并移除。票 04 遗留的
"徽标淡入是否恢复"就此裁决：**分层窗口上不做出现类透明度动画**；若日后要
出现动效，走非透明起步的路径（如缩放）并实测。

**打断安全**：全部 To-only（从当前值续走）+ WPF 默认 SnapshotAndReplace +
出现前 `BeginAnimation(null)` 清场，快速反复触发不留残影。

**端到端实测**（对运行中实例的两阶段像素探针，DPI 感知）：

- 减少动画（本机当前即此设置）：保持期内徽标满值可见，保持期一过 60ms 内
屏幕像素归零——即时退场，无残影；
- **运行中**把系统动画设置从关打开：同一窗口的下一次退场在保持期后 60ms
仍满值、560ms 后归零——退场不再是即时的，开关生效无需重启得证；
- 探针两阶段背靠背复用同一徽标窗口（出现→清场→再出现），无中间态残留。

**注意**：本机的"动画效果"当前是**关闭**状态，因此日常使用里徽标与面板的
退场表现为即时消失——这是遵守设置的正确行为，不是 bug。想看到淡出，在
设置 > 辅助功能 > 视觉效果里打开"动画效果"即可，无需重启拾语。
