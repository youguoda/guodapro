# 06 — 内容子类型识别

**What to build:** 条目除了"文本 / 图片"之外，再识别出**链接、邮箱、颜色值、文件路径**四种
子类型，并在列表中以对应方式呈现——颜色值旁边显示一块真实色块，链接与邮箱在按住修饰键时
变成可点击样式。用户也能按子类型筛选。

## 与徽标过滤器的关系要理清

拾语已有的 `ContentClassifier` 判断的是"**该不该弹翻译徽标**"，识别出 URL / 路径 / 数字
之后一律不弹。本票要的是另一件事：**这条记录是什么，好让列表把它显示得更有用**。

两者判定目标不同、阈值不同，**不要合并成一个函数**。一个说"别打扰用户"，
一个说"这东西长这样"。硬合在一起，将来改任何一边都会伤到另一边。

颜色值要同时认 `#RGB`、`#RRGGBB`、`rgb()`、`rgba()` 几种常见写法；
路径要区分本机路径与 UNC 路径；邮箱的本地部分要允许点、下划线、加号、减号、
百分号——参照实现在这一点上修过 bug，说明窄了会漏。

## Comments

### 交付（2026-09-25）

**两套判定严格分开**（票面要求）：`ContentClassifier` 问"该不该打扰用户"，
`SubtypeClassifier` 问"这东西长什么样"——不同的正则、不同的阈值、各自的
测试（分类 29 项 + 存储 4 项，全绿，总计 295）。识别：链接（整条 http(s)，
散文中提到的 URL **不**算）、邮箱（本地部分容纳 `._+-%`）、颜色
（`#RGB`/`#RRGGBB`/`rgb()`/`rgba()`，附 `SubtypeColor` 字节级解析）、路径
（盘符/UNC/Unix 根，存 `LocalPath`/`UncPath` 两值）。

**存储（v5 只增迁移）**：`sub_type` 列，Append 时写入；**幂等回填**在每次
打开时只挑 NULL 行补判（老库零成本升级，None 保持 NULL 不写噪音）。
筛选并入 `HistoryFilter.Subtype`，路径筛选项把两值合一（用户眼里路径是一
个概念）。管理与窄条两侧都加了子类型下拉，与关键词/日期/标签任意组合。

**呈现**：颜色条目正文左侧一块真实色块（44×22 圆角，解析出的颜色）；
链接/邮箱在**按住 Ctrl 时**（与票 14 的按键提示同一修饰键——样式与动作同源）
变为 accent 色 + 下划线，Ctrl+点击用系统默认程序打开（邮箱走 mailto:）；
释放时恢复 DynamicResource 引用，主题切换不受影响。

**待人工**：复制 `#1F6FEB`、一个网址、一个邮箱、一条 `C:\...` 路径 → 窄条
看色块/可点样式（按住 Ctrl）→ 子类型筛选验证 → 管理窗同查。
