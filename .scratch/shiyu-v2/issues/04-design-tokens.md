# 04 — 设计体系：色彩、字体、间距与明暗主题

**What to build:** 一套贯穿全应用的设计 token——颜色、字号、字重、行高、圆角、间距、
阴影——以及跟随系统或手动切换的明暗主题。所有现有窗口（徽标、面板、快速条、
管理窗口、设置）换上这套 token 之后视觉一致，主题切换即时生效且不闪烁。

## 这是我们相对参照实现的直接优势

参照实现（EcoPaste）**放弃了视觉身份**：零 token 覆盖、无自定义字体、无主色，
视觉上与任何一个用同款组件库的应用无法区分。对一个常驻屏幕边缘的小工具，
这是实打实的机会成本。我们捡起来。

**针对中文调，而不是照搬英文优先的默认值**：

- 中文没有词间空格，**行高要比英文更松**——正文建议 1.7 而非常见的 1.5，
  否则整段中文会糊成一块；
- 中文字体在小字号下 **500 与 600 字重几乎看不出差别**，层级要靠**字号与颜色**拉开，
  不要指望字重；
- 等宽场景（颜色值、快捷键、路径）需要一个同时覆盖中英文的回退链，
  否则中英混排会出现基线跳动。

**Blocked by:** None — can start immediately.

**Status:** ready-for-agent

- [ ] 颜色、字号、字重、行高、圆角、间距、阴影全部集中定义，界面中不出现硬编码值
- [ ] 明暗两套主题完整，可跟随系统或手动指定
- [ ] 切换主题即时生效，不闪烁、不需重启
- [ ] 现有五个窗口全部换用 token，视觉一致
- [ ] 中文正文行高经实际长段落检验，不糊成一块
- [ ] 层级靠字号与颜色建立，在中文小字号下依然清晰可辨
- [ ] 中英混排时基线稳定，等宽场景不出现字体跳动
- [ ] 文字与背景的对比度满足可读性要求，明暗两套都要
