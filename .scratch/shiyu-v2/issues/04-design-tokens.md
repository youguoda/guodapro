# 04 — 设计体系：色彩、字体、间距与明暗主题

**What to build:** 一套贯穿全应用的设计 token——颜色、字号、字重、行高、圆角、间距、
阴影——以及跟随系统或手动切换的明暗主题。所有现有窗口（徽标、面板、快速条、
管理窗口、设置）换上这套 token 之后视觉一致，主题切换即时生效且不闪烁。

## 这是我们相对参照实现的直接优势

参照实现（EcoPaste）**放弃了视觉身份**：零 token 覆盖、无自定义字体、无主色，
视觉上与任何一个用同款组件库的应用无法区分。对一个常驻屏幕边缘的小工具，
这是实打实的机会成本。我们捡起来。

**针对中文调，而不是照搬英文优先的默认值**：

- 中文没有词间空格，**行高要比英文更松**——正文建议 1.7 而非常见的 1.5，
  否则整段中文会糊成一块；
- 中文字体在小字号下 **500 与 600 字重几乎看不出差别**，层级要靠**字号与颜色**拉开，
  不要指望字重；
- 等宽场景（颜色值、快捷键、路径）需要一个同时覆盖中英文的回退链，
  否则中英混排会出现基线跳动。

**Blocked by:** None — can start immediately.

## Comments

### 交付（2026-09-25）

**架构：token 数据在 Core，App 只做编译与引用。**

- `Shiyu.Core/DesignTokens.cs`：两套调色板（12 个语义槽位）、可读性配对表、
  中文调过的字体链（UI：`Segoe UI, Microsoft YaHei UI`；等宽：
  `Cascadia Mono, Consolas, Microsoft YaHei UI`）、正文行高比例 **1.7**、
  字号五档、圆角四档、阴影两档、间距刻度。枚举叫 `AppTheme` 不叫
  `ThemeMode`——WPF 9 自带 `System.Windows.ThemeMode`，撞名会让每个使用处都要起别名。
- `ThemeManager` 把 Core 数据编译成资源字典：值字典（随主题换引用）+
  `Themes/Controls.xaml`（控件样式，只引用 token 不含值）。**切主题 = 换值字典
  的引用**，所有 `{DynamicResource}` 原地重解析，不重建窗口、不需重启。
  合并在代码里做而非 App.xaml——本机生成的 App.g.cs 缺 `InitializeComponent`
  （票 02 记录的坑），App.xaml 声明的资源根本不会加载。
- 跟随系统：仅 System 模式下每 5 秒读注册表 `AppsUseLightTheme`，实际变化才换。
- 设置：`AppSettings.Theme`（字符串序列化，默认跟随系统）；设置窗新增"外观"区，
  保存即生效（与其余设置一致）。CONTEXT.md 的设置范围同步更新。

**测试：新增 13 项，全绿（总计 239）。** 两套调色板槽位逐一相等、hex 合法、
两套 × 全部 11 个前景/背景配对 WCAG 对比度 ≥ 4.5（半透明墨水按配对背景
合成后测）、行高比例 ≥ 1.7 且行高按比例推导、两条字体链都含中文字体、
等宽链以真等宽开头、间距刻度严格递增、默认跟随系统、设置往返。

**窗口换装**：徽标、面板、快速条、管理窗、设置全部改用 token 引用；机检确认
五窗不再有任何字面颜色、字号、字重、行高、圆角、阴影。文字层级从"黑色+透明度"
改为语义色（Text/Secondary/Tertiary），透明度层次不再依赖主题猜测。

**边界与已知缺口**（留待票 12 或人工判断）：

1. **间距**：刻度已集中定义，但窗口内非对称布局边距（对齐到标签宽度的缩进、
   行内微调）仍是字面值——按"布局值不算视觉 token"的边界处理，票 12 重做
   主窗时统一上刻度。故第一条验收留待。
2. 非编辑态 ComboBox 与 DatePicker 弹层仍是系统 chrome：两主题下都可用可读，
   重模板是一整块工作，留给票 12 的新窗口。
3. ListBox 选中高亮仍是系统蓝，换 accent 高亮与票 13 的悬停动作一起做。

**人工验收清单**：开拾语 → 设置切"深色"保存，五个窗口看切换是否即时无闪烁
（徽标需复制一段英文触发）；看一段长译文行高是否松得开；管理窗中英混排与
设置里的等宽规则框基线是否稳定；小字号层级是否清晰。

### 人工验收第一轮（2026-09-25）

反馈三条：徽标不出现（两条）、字体偏小。

**徽标不出现——v1 潜伏 bug，已修。** 排查链（每步都以实测收口）：数据库证实
用户复制的英文句子已入库、分类器必放行 → HWND 探针证实徽标窗口显示/贴光标
定位/置顶/非激活/未 cloaked 全部正确 → `PrintWindow` 证实窗口内容绘制完好 →
屏幕级像素证实**没有合成上屏**。根因：v1 的淡入动画让窗口以 `Opacity 0`
出现，而 **WPF 对全透明的分层窗口表面跳过合成，0→1 的动画永远拿不到第一帧**
——徽标窗口"可见"但全透明，保持期一过就被隐藏。用户从未见过徽标，v1 的
显示路径此前从未被人眼验收过。与票 02 挖出的"动画时钟跟着合成帧走"同族。

修复：去掉淡入（满值直出），保留从已绘表面起步、实测可行的淡出；保持时长
1700→2000ms（规格 1~2 秒的上限）。端到端复测：徽标区域屏幕截取
9975/23232 像素为主题蓝；主屏与副屏（双屏均 1.5x）定位均验证正确。
**淡入是否以内容级动画的形式恢复，归票 05 动效体系一并裁决**（该票本就
要求统一的时长/缓动与"减少动画"适配）。

**字号 +1**：五档字号整体上调（10/11/12/13/14 → 11/12/13/14/15），行高按
1.7 比例自动跟随；徽标药丸随之变大（物理约 202×56）。对比度测试不受影响。
