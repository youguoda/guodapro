# 18 — 预览连接线

**What to build:** 一条曲线把预览面板与它所属的那一行连起来，两端各有一个圆点。
在列表中上下移动时，面板与曲线一起**滑过去**；首次打开时直接就位，不从上一个位置飞过来。

## 它解决的是一个真实困惑

预览面板浮在列表之外，用户看着它时并不总能确定"这显示的是哪一条"——
尤其是键盘快速上下移动的时候。一条线把归属说清楚了，而且不占任何额外的解释空间。

## 两个让它显得贵的细节

- **锚点是选出来的，不是固定的**：面板可能在行的左边、右边、上方或下方，
  曲线该从哪条边出发要按距离与朝向打分选，选错了线会绕一个难看的圈。
- **首次打开要瞬移，重定位才滑动**。反过来做的话，每次打开面板都会看到线从屏幕另一头
  甩过来——那不是精致，是故障感。

## 实现记录（2026-09-26）

- **锚点选边**：`PreviewConnector`（Core，8 用例）。卡片四条边中点各算一个候选，
  面板侧取朝向该候选的临边点；按距离打分，**穿过卡片或面板内部的连线直接罚
  1e6 淘汰**——不绕远、不穿自身由测试钉死。控制点沿主轴伸 40% 缺口宽度：横对
  卧 S、竖对立 S。
- **曲线层**：`ConnectorWindow`（App）。只盖住曲线跨度区域的小分层窗口，
  `WS_EX_TRANSPARENT|WS_EX_NOACTIVATE`——探针实测点在层内空白处点击落到下层
  应用（前台 hwnd 变为非本进程）。z 序压在预览面板正下方，线在面板边缘消失
  而非覆在其上。
- **瞬移首开/滑动重定位**：面板每次落位/滑动步进都广播物理矩形
  （`PanelMoved`），曲线随之重画——首次打开画在最终位置（无飞入），滑动时与
  面板同一 lerp 步进。减少动画时滑动退化为一步，曲线同样一步到位，连接关系
  仍清晰。
- **多屏/缩放**：几何全程物理像素（Core 算，测试钉），窗口 DIP 换算用它自己
  所在显示器的 scale。
- **连带修的产品 bug**：原 `PreviewPolicy` 悬停接管规则过宽——按住空格时指针
  掠过**任何**卡片都会把预览的所有权转给悬停规则（滚动就会关掉）。收紧为只在
  **面板正显示的那张卡**上悬停才移交。探针正是被它咬了一口才暴露的。
- **已知限制（如实记录）**：中文输入法开启时，搜索框持有焦点的状态下按空格
  可能被输入法吞掉（探针注入的合成键实测随机被吞，真实按键同理）——空格预览
  在输入法中文态不保证触发，悬停预览不受影响。后续可考虑对空框状态做
  IME-level 处理，暂不阻塞。

- [x] 面板在行的任意方位时，曲线都从合适的边出发，不绕远、不穿过面板自身
- [x] 在列表中移动时面板与曲线一起平滑过渡
- [x] **首次打开时面板与曲线直接就位**，不从上一次的位置飞入
- [x] 系统开启减少动画时，过渡关闭但连接关系仍然清晰
- [x] 多显示器与不同缩放下坐标正确
