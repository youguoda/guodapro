# 26 — 接管 Win+V

**What to build:** 用户可以选择让 `Win+V` 唤起拾语的窄条主窗，**代替 Windows 自带的
剪贴板面板**。默认关闭——这是一个夺取系统按键的行为，必须由用户明确开启。

## 为什么值得做

`Win+V` 是 Windows 用户**已经形成肌肉记忆**的按键。能接管它，意味着拾语不需要
教用户任何新键就能替换掉系统面板；不能接管，用户就得同时记两套。

## 为什么必须默认关闭且能可靠还原

`Win` 组合键无法通过常规的全局热键注册拿到，需要更底层的键盘介入手段。
这类手段有两个必须处理的后果：

1. **拾语崩溃或被强杀时，`Win+V` 必须回到系统行为**，不能把用户的按键永久吞掉；
2. 关闭这个开关后要**立即**还原，不能要求重启。

做不到这两条，这个功能就不该发布——夺走一个系统按键还还不回去，
比不做这个功能糟糕得多。

## 实现记录（2026-09-26）

- 结构：`WinVFilter`（Core 纯状态机，七测——只吞 Win+V（左右 Win 皆可）与
  尾随 V/Win 抬起【Win 抬键不吞干净会弹出开始菜单】，其余一切原样放行：
  纯打字、单按 Win、Win+R/E、先松 Win 再按 V、按住重复不重触发、接管后
  下一次组合恢复正常）+ `WinVHook`（Shiyu.Windows，WH_KEYBOARD_LL 装在
  泵消息的 UI 线程，裁决交给过滤器，触发经 SynchronizationContext 回 UI）。
- 还原的两条保证都是结构性的：钩子活在进程里——退出/强杀时操作系统自动
  摘除，Win+V 自回系统行为；关开关（或恢复备份设置）即刻 Dispose 卸钩，
  无需重启。App 启动与 Apply/恢复备份三处都调 ApplyWinVTakeover 对齐。
- 入口：设置·快捷键页新分区「系统按键」→「接管 Win+V」（默认关），
  说明含还原行为与「窄条」热键并存分工（两者都开时都能唤起窄条）。
  注入按键有意不过滤：用户自己的自动化工具同样该得到接管，拾语自身
  从不合成这组键、无环路可防（否则探针与 AHK 用户都会被拒之门外）。
- 探针实录：settings.json 置开 → 起实例 → 注入 Win+V（Win↓V↓V↑Win↑）
  → 窄条被唤起（bar after: True，探针全程系统面板未弹）；置关重启正常；
  结束后 settings.json 复原。其余 Win 组合不受伤由过滤器七测钉死。
- 追修（用户实测两连报）：①开关保存链路 bug 致「接管 Win+V」落盘 false、
  其余开关被一次保存静默清零（详见 ItemEditors 修复提交，用户设置已复原）；
  ②按住 Win 连按两次 V，第二次 V 原被放行——带着 Win 直达系统，系统剪贴板
  面板弹出。改为接管期间一切 V 按下皆吞、不重触发（防自动重复狂切窄条），
  过滤器测试断言连击全程吞下只触发一次。探针实测：按住 Win 双击 V，
  窄条唤起后保持、应用存活。
