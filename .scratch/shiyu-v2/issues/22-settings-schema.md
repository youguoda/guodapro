# 22 — 设置即数据

**What to build:** 把设置界面改造成由**一棵数据树**驱动：标签页 → 分区 → 设置项，
每一项声明自己的标识、控件类型、取值路径、关键词、父项与禁用条件。
文案按标识查，图标按标识查。界面本身不硬编码任何一项设置。

分区按**用户意图**组织，不按代码模块——"记录 / 历史 / 动作 / 界面 / 快捷键 / 数据 / 关于"，
而不是"常规 / 高级"。

## 为什么这是整个参照实现里最值得抄的结构

七十多项设置写成数据之后，**三件事是白送的**：

1. 设置内搜索——遍历数据树即可，不必为搜索另写一套索引；
2. 从任意位置深链到某一项——传一个标识就够；
3. 首次引导页复用同一批控件定义——一份数据，三处消费。

写成硬编码界面的话，这三件事要各写一遍，而且会各自腐烂。

## 一个要避开的坑

参照实现把十一项设置声明成了"分段控件"，渲染层却统一渲染成下拉框——
主题切换因此要点两次还看不到选项。**声明了什么就渲染什么**，
渲染层偷懒会让数据层的设计意图白写。
