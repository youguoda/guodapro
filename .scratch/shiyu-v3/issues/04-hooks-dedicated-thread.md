# 04 — 低级键鼠钩子迁到专用线程

**来源：** 优化报告 O-16；审计 A2 §2
**Blocked by:** —
**Branch:** `v3/hooks`（执行中）
**Status:** ready-for-agent

**What to build:**
- `Shiyu.Windows` 里一个专用钩子线程宿主：后台线程装钩并运行自己的消息循环；释放时在该线程卸钩并退出。
- `WinVHook`、`MouseDragHook` 改在专用线程装钩，回调逻辑不变，事件仍 Post 回 UI 线程。
- `SetWindowsHookExW` 失败可见：带回 Win32 错误码；App 回滚为未接管，并用托盘通知说明原因。

**为什么：** 钩子装在 UI 线程，而取词时 UI 线程 `Thread.Sleep` 最长 600 ms。期间全系统键鼠卡顿，钩子还可能被系统静默摘除；开着 Win+V 接管时，迟到的 Ctrl+C 会在剪贴板还原之后覆盖用户剪贴板。

**验收：**
- [ ] 两个钩子都不在 UI 线程安装（代码审读）
- [ ] 实机：开启划词徽标，连续拖动窗口标题栏 20 次，光标无停顿，之后拖选仍出徽标
- [ ] 实机：开启 Win+V 接管后按 Ctrl+Shift+Z 取词，1 秒后剪贴板仍是原内容
- [ ] 实机：关/开两个开关各 5 次，无异常
