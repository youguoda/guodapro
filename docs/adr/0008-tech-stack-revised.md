# ADR-0008：技术栈（取代 ADR-0006）

- 状态：已接受
- 日期：2026-09-22
- 取代：ADR-0006

## 背景

实施票 01 时探查开发环境，发现 ADR-0006 的事实基础有误。

### 更正：ADR-0006 的第 3 条理由建立在过期证据上

ADR-0006 选择 Qt 的第 3 条理由是"用户机器已具备 Qt、CLion、OpenCV、HALCON
工具链"。该判断来自 `PATH` 环境变量。**实测这些目录全部不存在**——
`D:\QT`、`D:\JetBrains`、`D:\HALCON`、`D:\Program Files\OpenCV410` 均已不在，
`PATH` 条目是旧环境的残留。

全盘搜索只找到一个 `Qt6Core.dll`，属于 NVIDIA Nsight Compute 自带，不是可用 SDK。
**Qt 并未安装。**

该条理由的实质是**完成风险**——个人项目最常见的死因是做不完。基于过期证据，
本评审替用户判断了"你熟悉这套工具链"。经直接询问，用户澄清**并不特别熟悉 Qt**。

### 环境实况

| | 状态 |
|---|---|
| .NET SDK 9.0.318 | 已安装，可立即使用 |
| MSVC 2022 Community (14.44) | 已安装 |
| CMake 3.31.2 | 已安装 |
| MinGW g++ | 8.1.0，对 Qt 6 过旧 |
| Qt | **未安装**（需数 GB 下载 + 账号） |
| NuGet | 可达，`Microsoft.Data.Sqlite` 可还原 |

## 决策

**C# / .NET 9 + WPF。**

## 理由

1. ADR-0006 已将 WPF 列为**第一顺位回头选项**，触发条件写的是
   "若『做完』的压力超过『省内存』"。当前情况恰好落在这句话上。
2. 用户不特别熟悉 Qt，而 Qt 路线还需先完成一次重量级安装。两项叠加使完成风险显著高于
   ADR-0006 作出决策时的估计。
3. .NET 9 已就绪，零安装成本。
4. WPF 在"小而精美"这一项上的单位投入产出明显优于 Qt Widgets + 手写 QSS。
5. 剩余的 Win32 需求（`WS_EX_NOACTIVATE` 窗口、`RegisterHotKey`、
   `AddClipboardFormatListener`、`SendInput`、排除标记）在 .NET 中均为成熟的
   P/Invoke 场景，先例充足。

## 后果

- **常驻内存高于 C++ 方案**，量级差异为数十 MB。这是本次取舍中真实付出的代价。
- **NativeAOT 不适用于 WPF**，冷启动无法压到原生水平。缓解：见 ADR-0006 已确立的
  结论——托盘常驻程序的冷启动每日仅一次，真正的指标是**热路径**。
- **托盘图标使用 `Shell_NotifyIcon` P/Invoke，不引入 WinForms。** 理由：WPF 进程加载
  整套 WinForms 仅为一个托盘图标，与"内存小"相悖。
- **单一隐藏消息窗口同时承载托盘回调、`WM_CLIPBOARDUPDATE` 与日后的热键消息。**
  本应用无论如何都需要一个消息窗口来接收剪贴板通知，复用它可减少总代码量。

## 不受影响的部分

ADR-0001 ~ 0005、ADR-0007 **全部不变**。它们描述的是产品行为、触发模型、数据策略与
隐私边界，不依赖 UI 技术。spec 中的 68 条 user story 与 14 张票同样不变——
仅个别提及 Qt 的实现描述需改写。

## 回头选项

若常驻内存在实测中确实不可接受，回头路依次是：剥离 WPF 改用纯 Win32 + P/Invoke 外壳；
或退回 ADR-0006 的 C++ 方案。二者代价都很高，应在有**实测数据**后再考虑，
而非凭感觉。
