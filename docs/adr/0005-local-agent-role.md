# ADR-0005：本地 agent 的角色

- 状态：已接受
- 日期：2026-09-21

## 背景

原始需求为"翻译和复制可以接入我本地的 agent"。但 ADR-0004 将"整理"定义为
人工组织（标签、置顶、筛选），LLM 被挤出了剪贴板一侧的核心流程，需重新界定其位置。

## 决策

1. **翻译一侧**：agent 是可插拔翻译后端的第二个实现（见 ADR-0002），
   用于离线或隐私场景。
2. **剪贴板一侧**：agent 的唯一入口是**对用户明确选中的条目执行一个动作**——
   总结、合并成笔记、改写、建议标签。

**不做**任何自动的、后台的、逐条的 LLM 处理。

## 理由

- 一个机制覆盖全部需求。所谓"收集篮"无需作为独立概念存在：多选几条 +
  "合并成笔记"就是收集篮。
- 隐私边界与 ADR-0001 的徽标原则完全一致：**未经用户明确动作的内容，永不外送。**
- 与翻译后端同形，两侧共用一套流式调用与错误处理。
- 自动打标签虽能缓解"手工标签难以坚持"的问题，但需逐条外送全部复制内容，
  成本与隐私均不划算，且与上一条原则冲突。

## 后果

- "手工维护标签体系难以长期坚持"这一风险**仍然存在**，仅由"选中后请 agent
  建议标签"部分缓解。若日后该风险成真，需重新审视本决策。
- 不存在任何后台 LLM 流量，agent 未运行时应用全部功能（翻译除外，可切云端）正常。
