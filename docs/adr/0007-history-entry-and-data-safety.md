# ADR-0007：历史的两个入口，与不加密的取舍

- 状态：已接受
- 日期：2026-09-21

## 背景

剪贴板历史存在两种使用场景，对窗口的要求相反：

| | 快速粘贴 | 翻检整理 |
|---|---|---|
| 频率 | 每日数十次 | 每周数次 |
| 目的 | 找回最近某条，粘到光标处 | 搜索久远记录、打标签、批量选给 agent |
| 需要的窗口 | 小、贴手边、选完即消失 | 大、有筛选器、可久留 |

同时，ADR-0004 决定无限存储一切格式，数据安全成为必须表态的问题。

## 决策

### 入口

**两个入口，两种形态**：

- **快速条** — 热键唤出，出现在光标旁，键盘上下选、回车粘贴、立即消失。
- **管理窗口** — 点击托盘图标打开，含筛选器、标签、批量选择，可久留。

### 数据安全

1. **不加密。** 依赖 Windows 用户账户隔离。
2. **排除规则成为唯一防线**，因此强制要求：
   - 预设排除清单开箱可用（常见密码管理器、银行/支付类窗口）
   - 一键清空、按时间段删除
3. **数据位于 `%LOCALAPPDATA%\Shiyu\`。** 该目录本机专属、不漫游，
   OneDrive 默认不同步。**在不加密的前提下，"数据不离开本机"完全依赖放对位置。**
4. 若日后提供自定义数据库位置，选中同步目录时**必须明确警告**。

## 后果

### 第二处 SendInput 时序脆弱点

**快速条必须接受焦点**（需键盘导航），这与 ADR-0001 中徽标/面板的
`WS_EX_NOACTIVATE` 规则正好相反。粘贴时须先将焦点交还原窗口，再发 `Ctrl+V`。

这与 ADR-0003 的取词时序是**同一类缺陷**，应由同一模块、同一套机制处理。
两者共同构成本项目最大的技术风险。

### 数据安全的边界

不加密可防住的：什么都防不住——一旦文件离开本机即为全裸。
放在 `%LOCALAPPDATA%` 只是降低文件被动离开的概率，不是保护。

用户已知悉并接受：备份、同步、二手硬盘、误发文件夹等场景下，
数年明文剪贴板历史将完全暴露。

### UI 成本

两块 UI 均需编写与美化。在 WPF 的前提下（ADR-0008），
这是实打实的工作量。

## 被推翻的备选

- **只做一个完整窗口** — 少写一块 UI，但每日数十次的快速粘贴要弹出带筛选器的
  大窗口，最常用的操作被最少用的功能拖重。
- **只做快速面板** — 批量选条目交给 agent、翻检久远记录在小面板中极痛苦。
- **SQLCipher 整库加密 + DPAPI 管密钥** — 对用户透明、无需输密码、全文搜索照常
  （页层加解密，列级加密会使全文索引失效）。可防住文件被拿走、备份泄露、
  旧电脑未擦净。因需自行集成（默认的 SQLite 提供程序不自带）而落选。
  **若日后对隐私的顾虑上升，这是第一顺位的回头选项。**
- **整库加密 + 开机输密码** — 安全性最高，但与"开机即用"的托盘工具气质冲突。
