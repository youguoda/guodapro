# TieZ → 拾语：功能与设计采用梳理

> 依据：[TieZ 调研报告](2026-09-26-tiez-clipboard-analysis.md)（2026-09-26，源码级取证）
> 本文回答一个问题：**TieZ 的哪些东西值得进拾语，怎么落，哪些明确不碰。**
> 每项给：TieZ 的做法（带文件）→ 拾语的落地映射（到现有代码）→ 成本/风险 → 验收要点。

## A. 建议采用——功能

### A1. 顺序粘贴（P0）

**TieZ 做法**（`services/paste_queue.rs`）：`Vec<i64>` 条目 ID 队列；用户连续触发（如 V、V、V）时每步取队头写入剪贴板并合成粘贴；每步间 20ms settle；检测 `GetAsyncKeyState(0x12)`（Alt）判断用户是否还在连按，并用 SendInput 重按 Alt 维持连按状态；步进完成后按规则清理已贴条目（跳过置顶/带标签的）。

**拾语落地映射**：
- Core 新增 `PasteQueue` 纯状态机（入队/步进/完成/清理规则），时钟注入，照 `PreviewPolicy` 的样式写测试
- 注入复用 `WindowsCapturePlatform.SendPasteKeystroke`（Ctrl+V 路径）或 A3 的可选模式
- 修饰键维持**必须按拾语的钩子纪律重做**：绝不在回调内同步注入（票 18/WinVHook 的教训——钩子内注入会重入摘钩），一律 Post 到 UI 线程
- 入口设计：窄条里多选条目（已有 Ctrl 多选？没有——需补"加入队列"动作或右键"顺序粘贴"），或复制时自动入队（可配置）
- UI 反馈：队列进行中窄条显示步进指示（"3/7"）

**风险**：连按时序与不同应用的粘贴消化速度差异（20ms 是 TieZ 的经验值，需实测）；与置顶/收藏清理规则的交互（默认不删，仅 use_count+1——与拾语 `BumpUse` 现状一致）
**验收要点**：记事本/Word/终端三种目标连贴 7 条无错序；Alt 维持不产生粘滞修饰键（WinVHook 修复同款断言：事后 GetAsyncKeyState 全抬）

### A2. 预览脱敏（P0）

**TieZ 做法**（`src/shared/lib/utils.ts` 的 `formatSensitivePreview`，全仓唯一有单测的函数，19 用例）：正则族识别身份证/手机号/邮箱，预览层打码显示，原文不动。

**拾语落地映射**：
- Core 新增 `SensitiveMask.Mask(text)`：身份证（18 位含校验位可选）、手机号（1[3-9]+9 位）、邮箱、**加一类 TieZ 没有的：API key 模式（sk- 开头 20+ 位）**——这是我们从自身实践（DeepSeek key 不回显）得出的敏感面
- 应用在两处：预览面板 `TextBody`（票 17 的窗口）与库窗口详情，显示层替换 `123****5678` 式掩码；**按住 Ctrl 临时显示原文**（预览窗已是非激活，Ctrl 状态已有全局监听经验——票 14 的 Ctrl 提示）
- 条目本身、搜索、粘贴均用原文——脱敏只在"看"的层

**成本**：低（纯函数 + 测试 + 两处显示层）
**验收要点**：掩码不进数据库、不进剪贴板；搜索"手机号"仍命中原文；Ctrl 按住显示/松开恢复

### A3. 粘贴模式三选一（P1）

**TieZ 做法**（`services/clipboard_ops.rs::send_paste_keystroke`）：`app.paste_method` 设置三选一——`shift_insert`（默认）/ `ctrl_v`（扫描码）/ `game_mode`（逐字符 `KEYEVENTF_UNICODE` + IME 状态保存恢复）。

**拾语现状**：`WindowsCapturePlatform.SendWithControl(VkV)` = Ctrl+V，且已正确做"先释放用户仍按住的修饰键"（这点 TieZ 同款，说明是共识坑）。**缺口**：终端/部分游戏/远程桌面对 Ctrl+V 不响应或不一致。

**拾语落地映射**：
- `ISelectionPlatform` 加 `SendPasteKeystroke(PasteMethod)`；Windows 实现三分支
- 设置项 `paste.method`（分段控件：Ctrl+V / Shift+Insert / 逐字符），放"动作"页；划词翻译的粘贴路径同享
- game_mode 的 IME 状态保存恢复照抄思路（先 `GetKeyboardLayout`/IME 开关快照，逐字符注入，恢复）——注意逐字符模式对回车/Tab 等 VT 键需要转义映射

**成本**：低-中（game_mode 的 IME 细节是唯一硬点）
**验收要点**：Windows 终端（conhost/WT）贴多行文本三种模式结果对比；游戏模式后 IME 状态与粘贴前一致

### A4. 外部编辑器协作回写（P1）

**TieZ 做法**（`app/commands/file_cmd.rs` + `services/content_handler.rs`）：条目一键送外部编辑器，监视存盘，自动回写历史。

**拾语落地映射**：
- `HoverActions.All` 第 11 个动作 `"edit"`（现有清单：copy/paste/plain/open/locate/pin/favorite/note/group/delete）
- 实现：写 `%TEMP%\shiyu-edit\<id>.txt`（保留扩展名感知：代码条目 .md/.txt）→ `Process.Start` 系统默认或用户配置编辑器 → `FileSystemWatcher` 监变更（防抖 1s）→ `_store` 更新 text（新 fingerprint，不算新条目）→ 窄条卡片刷新
- 与备注体系的关系：备注是"给条目贴脸"，编辑是"改条目本体"——两个动作并存，菜单里相邻
- 设置项：`edit.editor`（空=系统默认）

**成本**：中。**验收**：编辑器保存后窄条无刷新闪烁（INPC 原位更新）；编辑器未保存退出不留Watcher 泄漏

### A5. 多色标签（P1）

**TieZ 做法**：`entry_tags` 表 + TagManager（90KB 组件）+ 每标签一色，卡片上色点扫读。

**拾语落地映射**：
- 迁移 v12：`tags` 表加 `color INTEGER`（存 0-7 调色板索引而非自由 RGB——与 DesignTokens 的克制一致）
- `BarCard` 已有 `GroupBadge` 的显示位，标签色点排在同排；标签过滤 UI（TagFilter 下拉）每项前加色点
- 标签管理入口：现有 `RefreshTagChoices` 扩展成小管理弹窗（改名/设色）

**成本**：低-中。**验收**：旧库迁移无损（color 默认）；色点在浅/深主题都可辨（过 DesignTokens.ReadablePairs 式检查）

## B. 建议采用——交互与设计

### B6. 全局"V+数字"盲粘（P2）

TieZ 的修饰键+数字直接粘贴历史第 N 条。拾语已有窄条内数字键粘贴；缺的是**不开面板**的全局版。落地：`HotkeyRegistry` 注册 `Alt+1..9/0`（或用户自定义修饰键），动作=取当前过滤视图第 N 条直接走 Paste 路径。注意与系统/常用软件的 Alt+数字（浏览器标签切换是 Ctrl+数字，Alt+数字多数空闲）冲突检测——拾语热键注册已有冲突警告（新手引导里的实时冲突检查可复用）。

### B7. 中键呼出（P2）

TieZ 用低级鼠标钩子实现中键呼出窄条。拾语不需要鼠标钩子：`RegisterRawInput` 或干脆热键方式注册鼠标中键不可行（HotkeyRegistry 是键盘）——最省事的做法是 XButton1/XButton2（鼠标侧键）作为可配热键，或经 Raw Input 监听 Middle。**建议先用侧键（多数鼠标有且闲置），真中键等用户反馈再上 Raw Input。**

### B8. 边缘停靠收纳（P2，需设计）

TieZ：窗口贴边后缩成 3px 触条，光标触碰唤出（150ms 轮询检测——**这个实现不抄**）。拾语落法：`OnLocationChanged` 判断窄条边缘贴近工作区边界（无轮询）→ 进入停靠态：窗口缩为 6px 触条（或完全隐藏+边缘 1px 热区）→ 光标进入热区唤出（`MouseEnter` 即可，窗口极窄但存在）→ 拖离边缘恢复。与"光标旁呼出"并存：停靠是空间范式、呼出是时机范式，设置里二选一或并存皆可。**先做设计票再动工。**

### B9. 图片/文件回环指纹（P2，审计项）

TieZ 用 `LAST_APP_SET_HASH / _ALT / _IMAGE_VISUAL_HASH` 三条指纹防"自己写回剪贴板的内容被自己记录"。拾语文本回环已防（`newest.Text == snapshot.Text` + Touch），**图片回环待审计**：贴图片条目后管线是否会把同一张图再记一条？若会，加视觉哈希（缩略图字节 SHA256 已有——`ContentFingerprint` 扩一个 image 分支即可）。先写一票审计探针，确认问题存在再修。

## C. 工程/机制层面借鉴

| TieZ 机制 | 对拾语的意义 | 动作 |
|---|---|---|
| 合成按键前释放全部修饰键 | **拾语已同款**（`SendWithControl`），互相印证 | 无 |
| 窗口隐藏后恢复上一前台（LAST_ACTIVE_HWND） | 拾语已有 `ForegroundWindow._returnTo` | 无 |
| game_mode 的 IME 快照恢复 | A3 采用范围的组成部分 | 随 A3 |
| 同步数据模型（op 批次+tombstone+blob 外置） | 若将来做"备份上云"可参考数据结构（实现不抄） | 存档备查 |
| Rust 分层骨架 | 与拾语 Core/Windows/App 分层同构，印证方向 | 无 |
| 巨型文件教训 | **拾语自查：`BarWindow.xaml.cs` 已 2946 行**，TieZ 病的苗头 | 见 §E |

## D. 明确不采用（记录理由，防反复）

1. **WebDAV/MQTT 同步、验证码秒传、局域网传输**：与拾语宪法"历史绝不离开机器"正面冲突；TieZ 的实现（明文 payload、零鉴权服务器、默认种子作者公共 broker）恰是该类功能的反面教材。**触发条件写死**：除非完成端到端加密设计评审 + 默认关闭 + 用户显式开启三件套，否则不重开此议题。
2. **主题商店/云端评分**：需要服务端账号体系与运营，个人域名单点（TieZ 的更新/公告/商店全绑 `tiez.name666.top`，域名失守=通道失守）。拾语的更新已走 GitHub Releases（票 28），基础设施零自持。
3. **Emoji 面板**：系统 Win+. 已覆盖；与"记录-回贴-翻译"的定位弱相关，纯维护负担。
4. **AI 公共 fallback 端点**（TieZ 默认 LongCat）：把用户内容引向作者控制的端点是反模式；拾语"用户自持 key、空则提示配置"的现状是对的。
5. **每日公告 ping/遥测**：与本地优先叙事冲突；版本信息随更新检查（用户主动）已足够。
6. **7 套主题+3D 动效**：拾语票 30 的 Fluent 改造（另一线进行中）已覆盖现代质感；主题广度是维护税。

## E. TieZ 有、拾语已有等价物（防误判差距）

| TieZ 卖点 | 拾语等价物 | 拾语优势点 |
|---|---|---|
| 四类内容采集 | 同（文本/富文本/图片/文件） | 图片缩略+原图保留策略更完整（v11 宽高入库） |
| 历史搜索/置顶/使用计数 | 同 | 子类型识别（链接/邮箱/颜色/路径）+ 分组体系更细 |
| 非激活窗口呼出 | 同 | 拾语多一层 WM_MOUSEACTIVATE 拦截（TieZ 疑缺） |
| 全局快捷键+录制 | 热键+新手引导冲突检测 | 拾语有 Win+V 接管且不粘滞 |
| 自动更新 | 同为"检查-下载-安装" | 拾语有校验+两阶段交换+回滚，TieZ 无回滚叙事 |
| 敏感项本地加密 | 拾语排除标记+凭据不回显 | TieZ 非 Windows 明文 |
| 多语言 | 拾语中文优先单语 | 定位选择，非差距 |

**结论：真正的能力缺口只有 §A/§B 的 9 项；其余"差距"要么是定位不同（同步），要么是我们已更优。**

## F. 自查：我们自己的 TieZ 病苗头

`BarWindow.xaml.cs` **2946 行**，集中了：卡片构建、分组、过滤、拖出、上下文菜单、键盘模型、预览编排。TieZ 的 `setup.rs`（50KB）和 `TagManager.tsx`（90KB）就是这样长出来的。**建议在 v3 开一张重构票**：按现有注释分区自然切——`BarCards`（卡片+模板）、`BarFilters`（过滤/分组）、`BarInteractions`（拖出/菜单/键盘）、`BarPreview`（预览编排），行为不变、探针回归（窄条探针已 25 项，正好做安全网）。**在加 A1-A5 任何一项之前做**，否则每项都往 3000 行文件里塞。

## 建议票面顺序

1. **F（BarWindow 拆分）**——一切新功能的地基
2. **A2 脱敏预览**（最小、独立、纯 Core）
3. **A1 顺序粘贴**（P0 价值最大）
4. **A3 粘贴三模式 → A4 外部编辑器 → A5 多色标签**（各自独立可并行）
5. B6-B9 按反馈排期
